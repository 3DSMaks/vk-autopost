# Исправление изображений в постах ВК

## Что исправлено

- Изображения скачиваются напрямую с сайта новости с Referer и преобразуются в JPEG через Pillow. Внешний конвертер wsrv.nl больше не нужен.
- Поддержаны метатеги в любом порядке, lazy loading, srcset и URL без расширения.
- Изображение RSS остаётся запасным кандидатом, даже если на странице найдены нерабочие ссылки.
- Фото загружаются через photos.getWallUploadServer → multipart photo → photos.saveWallPhoto, а полученные photo-идентификаторы передаются в wall.post.
- Можно использовать отдельный пользовательский VK_PHOTO_TOKEN для фото, сохранив VK_TOKEN для публикации.
- При ошибке загрузки всех изображений пост не публикуется и новость не отмечается как опубликованная. Ранее программа подавляла ошибку и выпускала текст без фото.
- Удалены ненадёжные обходные пути через GIF-документы и карточки ссылок.

## Установка в существующий GitHub-репозиторий

1. Замените `post.py` и `.github/workflows/post.yml`, добавьте `requirements.txt`. Файл `seen.json` в работающем репозитории оставьте свой, чтобы сохранить историю публикаций. `test_post.py` и README можно также добавить.
2. В **Settings → Secrets and variables → Actions** сохраните текущие `VK_TOKEN` и `GEMINI_API_KEY`.
3. Если VK_TOKEN — ключ сообщества, добавьте секрет **VK_PHOTO_TOKEN**: пользовательский API-токен администратора данного сообщества с доступом к фотографиям (`photos`), полученный через разрешённую авторизацию приложения VK. Ключ сообщества не является пользовательским токеном. Если VK_TOKEN уже пользовательский и позволяет загрузку фото, отдельный секрет не нужен.
4. Для локальной проверки: `python -m pip install -r requirements.txt`, затем `python post.py --check-vk` при заданных переменных окружения. Проверка получает адрес загрузки, ничего не публикует и не загружает.
5. В **Actions → Пост в ВК → Run workflow** режим `check` проверяет доступ без публикации, режим `publish` публикует одну настоящую новость. После изменения кода проверка запускается автоматически. Расписание остаётся прежним — каждый час.

Workflow берёт актуальную main, включая историю seen.json, даже при повторном запуске старого задания. Перед сохранением истории получает изменения main через rebase.

Токены храните в Secrets, не вставляйте их в исходный код. Изменение кода не выдаёт токену недостающих прав: при ошибках 5/7/15/27/28 в журнале будет подсказка о проверке ключа и доступа администратора.

## Проверки

`python -m unittest -v test_post.py`

Автоматические тесты используют подменённые ответы сети: проверяют поиск и преобразование изображений, токен загрузки, формат вложений, запасной URL, отказ сервера и отсутствие публикации/изменения seen.json при сбое. Реальная публикация с ключами владельца из этой среды не проверялась.

`python post.py --dry-run` читает RSS и страницу новости, но не обращается к Gemini/ВК и не публикует пост.
