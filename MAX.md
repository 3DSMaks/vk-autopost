# Автопостинг в канал MAX

Те же новости, что в Telegram: темы чередуются через пост: игры, кино, игры…; пост с 1–3 фото, текстом и ссылкой «Источник». Своя история опубликованного — seen_max.json. VK и Telegram не затрагиваются.

## Подключение

1. Платформа MAX для партнёров (business.max.ru) или мини-приложение «MAX для бизнеса»: профиль самозанятого/ИП/организации → Чат-боты → создать бота. Токен: Чат-боты → ⋮ → Настройки → копировать токен.
2. В приложении MAX откройте канал → Подписчики → Добавить подписчиков → найдите бота → назначьте администратором с правом публикации (write). Первого бота-администратора можно назначить только через интерфейс мессенджера.
3. ID канала — числовой (например -71234567890123). Как получить: dev.max.ru → «Получение ID чата или канала».
4. GitHub → Settings → Secrets and variables → Actions → Secrets: MAX_BOT_TOKEN и MAX_CHAT_ID. GEMINI_API_KEY уже есть.
5. Actions → «Новости в MAX» → Run workflow → check — проверка без публикации; publish — одна настоящая новость.
6. После успешной проверки добавьте Variables → MAX_ENABLED = true. Расписание: каждые 30 минут (на 20-й и 50-й минуте). Для остановки — false.

## Технические детали

- API: platform-api2.max.ru, токен в заголовке Authorization (без Bearer).
- Сервер MAX подписан сертификатом Минцифры — цепочка (Russian Trusted Root CA + Sub CA) лежит в russian_trusted_ca.pem. Промежуточный сертификат действует до марта 2027 — тогда файл нужно обновить с https://gu-st.ru/content/lending/ (корневой SHA-256 D2:6D:2D:02:…:CA:8E:CF:31).
- Фото: POST /uploads?type=image → загрузка поля data → {"photos": …} во вложение; на attachment.not.ready — повтор с паузой.
- Токен не печатается в логах. При сетевой ошибке отправки сначала проверьте канал, не запускайте повторно вслепую.

Тесты: python -m unittest -v test_max.py
